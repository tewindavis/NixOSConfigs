# /etc/nixos — Agent Guide

Personal NixOS flake config for user `td`, managing three hosts via Nix Flakes
+ Home Manager. This file is the entry point for an agent working in this
repo; deep-dive references live in `docs/` (linked below) — read the ones
relevant to the task rather than everything up front.

For the human-facing feature tour (keybindings cheat sheet, aesthetic
rationale, fresh-install steps), see `README.md`. This file is the
technical/agent-facing counterpart: where things live, how to change them
safely, and the gotchas already paid for.

## Repository layout

```
flake.nix                  # inputs, forAllSystems, mkHost, formatter, checks
hosts/<name>/
  configuration.nix        # imports modules for this host + host-only settings
  hardware-configuration.nix  # generated by nixos-generate-config, don't hand-edit
modules/
  core/          default.nix   # settings shared by every host (locale, nix.gc, pipewire, printing, ...)
                 secrets.nix   # sops-nix wiring (inert until sops.secrets.* declared)
  desktop/       default.nix   # Thunar, fonts, archive support; imports hyprland.nix
                 hyprland.nix  # greetd/tuigreet, portals, polkit, gnome-keyring
  hardware/      framework.nix, nvidia.nix, utm.nix, bluetooth.nix   # per-host opt-in modules
  services/      syncthing.nix, vpn.nix
  dev/           rl-binary.nix   # ghidra/radare2/gdb + RL Python env, dl-prototype only
users/td/
  home.nix       # Home Manager: packages, dotfiles, Hyprland/waybar/dunst/etc config, shell scripts
  nixos.nix      # the `td` user account definition (groups, shell)
  hypr/hyprland.lua, waybar/, wofi/, wlogout/, swayosd/, ghostty/, nvim/   # linked dotfiles
secrets/secrets.yaml        # sops-encrypted; edit only via `sops secrets/secrets.yaml`
.sops.yaml                  # sops age-key recipients per host
treefmt.nix                 # nixfmt + statix + deadnix, run via `nix fmt`
```

**Convention:** a host's `configuration.nix` is just an `imports` list plus
host-only settings (bootloader, hostName, CPU tuning). Shared logic always
lives in `modules/`, never duplicated across hosts. All three hosts share one
Home Manager profile (`users/td/home.nix`, wired in `flake.nix`); there is no
per-host home.nix.

## Common tasks

**Add a system package (all hosts):** `modules/core/default.nix`
`environment.systemPackages`.
**Add a user package / dotfile / shell alias:** `users/td/home.nix`.
**Add host-only hardware/service config:** new or existing file under
`modules/hardware/` or `modules/services/`, then import it from that host's
`configuration.nix` only.
**Add a new host:** create `hosts/<name>/{configuration.nix,hardware-configuration.nix}`,
add a `mkHost { hostname = "<name>"; system = "..."; }` entry in `flake.nix`.

## Build, check, format

```bash
sudo nixos-rebuild switch --flake .#<hostname>   # apply (hostname must match networking.hostName)
nh os switch                                      # nicer wrapper, diffed switch; reads NH_FLAKE=/etc/nixos
nix flake check                                   # validates formatting + that all 3 hosts evaluate
nix fmt                                            # nixfmt + statix + deadnix over the whole tree
```

Always run `nix fmt` before committing — treefmt is the formatting source of
truth (`treefmt.nix`), not manual style matching.

There is no host named "current machine" — always pass the explicit
`#hostname` flake attr matching `networking.hostName` in that host's
`configuration.nix`.

## Secrets (sops-nix)

Encrypted at rest in `secrets/secrets.yaml`, decrypted at activation using
each host's own SSH host key. Only `framework` is enrolled as a recipient
today. Full workflow (enrolling a new host, adding a secret, referencing its
decrypted path): **`docs/secrets.md`**.

## Desktop (Hyprland / Tokyo Night rice)

Keybindings, waybar custom-module scripts, and the wallpaper/screenshot/
recording tooling are all defined in `users/td/home.nix` (shell scripts) and
`users/td/hypr/hyprland.lua` (binds/autostart). Reference + what each script
actually does: **`docs/desktop.md`**.

## Known gotchas / tribal knowledge

Before touching Hyprland, waybar scripts, NVIDIA, or the RL Python env, skim
**`docs/gotchas.md`** — it captures non-obvious bugs already hit and fixed
(Hyprland 0.56 Lua dispatch syntax, opacity `override` keyword, hyprsunset's
IPC socket vs CLI, etc.) so they don't get re-discovered the hard way.
